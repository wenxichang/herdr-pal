# Herdr Pal 独立安装包设计

## 1. 背景与目标

当前 Release Bundle 同时携带 Herdr 和 Herdr Pal。后续安装包只发布 Herdr Pal，安装器负责
发现本机 Herdr；缺失时下载已验证版本，不兼容时先征得用户同意再安装兼容版本。

本次目标：

- Bundle 不再包含 Herdr 二进制，也不再要求打包机编译 Herdr。
- 安装器只使用明确维护的 Herdr 兼容名单，不追随未经验证的最新版本。
- 复用兼容的现有 Herdr，不覆盖 Homebrew、mise、Nix 或其他外部安装。
- 下载内容必须经过来源、SHA-256、平台、版本和公共协议校验。
- 保持现有 Pal 配置、Startup 插件和可选 live-handoff 安装体验。

## 2. 兼容策略

兼容名单由 Herdr Pal 仓库维护，并在构建 Bundle 时写入安装器。首个名单只有：

| Herdr 版本 | 公共协议 | 用途 |
| --- | ---: | --- |
| `0.7.5` | `17` | 当前已完成 Pal、Startup 插件和真实环境联调的版本 |

Herdr 必须同时满足以下条件才可复用：

1. `herdr --version` 返回名单中的版本。
2. `herdr api schema --json` 返回协议 `17`。

安装器不以“版本号大于最低版本”推断兼容性。新增 Herdr 版本必须先完成 Pal 验证，再显式加入
名单。安装器也不直接执行 Herdr 官方 latest 安装脚本，避免未来最新版协议变化导致旧 Pal
被动安装不兼容版本。

## 3. 安装包与发布产物

单平台 Bundle 只包含：

```text
herdr-pal-bundle-<Pal版本>-<目标>/
  herdr-pal
  install.sh
  README.md
```

支持目标保持不变：

- `darwin-amd64`
- `darwin-arm64`
- `linux-amd64`
- `linux-arm64`

归档名称改为 `herdr-pal-bundle-<版本>-<目标>.tar.gz`，同时生成同名 `.sha256`。构建入口不再
接受 `--herdr-source`、`--herdr-binary` 或 `--herdr-commit`。

构建脚本根据目标平台把以下发布元数据写入 `install.sh`：

- 兼容 Herdr 版本。
- Herdr 公共协议。
- 对应平台的官方发布 URL。
- 对应平台的 SHA-256。

## 4. Herdr 发现与选择

用户选择安装目录后，安装器按顺序检查：

1. `<安装目录>/herdr`。
2. `PATH` 中的 `herdr`，并解析成实际绝对路径。

同一路径只检查一次。每个候选都执行版本和 Schema 协议检测：

- 第一个兼容候选直接作为后续配置使用，不下载 Herdr。
- 候选存在但不兼容时，安装器记录路径、检测到的版本和协议，继续查找其他候选。
- 如果后续找到兼容候选，仍直接复用兼容候选。
- 所有候选均不兼容时，安装器显示诊断并询问是否把兼容版本安装到用户选择的目录。
- 用户拒绝更新时立即退出，且此时还没有安装 Pal、写入配置或修改 Herdr 配置。
- 完全没有 Herdr 时，安装器明确提示并自动下载安装兼容版本，无需额外确认。

外部候选无论是否兼容都不被覆盖。需要安装兼容版本时，目标固定为
`<安装目录>/herdr`；该目标已有普通文件时才按现有备份规则替换。

## 5. 下载与安装事务

安装器使用 `curl` 下载官方单文件二进制；缺少 `curl` 时明确失败并给出手工下载提示。下载
过程使用 HTTPS、重定向、连接超时、总超时和有限重试。

下载文件先保存在 `mktemp -d` 创建的临时目录，随后依次验证：

1. SHA-256 与兼容名单中的固定摘要一致。
2. `file` 输出与 Bundle 目标平台及架构一致。
3. 临时二进制可执行且 `--version` 返回预期版本。
4. `api schema --json` 返回公共协议 `17`。

任何验证失败都删除临时内容并终止，不安装 Pal、不写配置。验证通过后才使用临时文件和
原子重命名安装 Herdr。

Pal 二进制继续按现有方式安装：目标存在时先创建带 UTC 时间戳的备份，再通过同目录临时
文件原子替换。Herdr 或 Pal 安装失败时恢复本次已经替换的目标文件。

## 6. 配置与运行中 Herdr

确定 Herdr 路径并安装 Pal 后，安装器继续：

1. 读取用户输入的 HPRP WSS URL 和机器 Key。
2. 调用 `herdr-pal setup` 写入 Pal 配置和 Herdr Startup 插件。
3. 使用选定 Herdr 的绝对路径调用 `herdr config check`。
4. 检测 Herdr Server 是否正在运行。

如果复用的是兼容 Herdr，Startup 插件绑定该现有绝对路径。如果安装了兼容版本，则绑定
`<安装目录>/herdr`。

检测到运行中 Herdr 时，安装器仍询问是否执行 `server live-handoff`：

- 复用兼容版本时，使用该版本执行现有 handoff 流程。
- 新安装兼容版本时，以新二进制作为 `--import-exe`。
- 用户拒绝或 handoff 失败时保留现有服务，并提示稍后手工重启。

## 7. 错误信息与安全边界

安装器错误必须区分以下阶段：平台检查、Herdr 发现、版本解析、Schema 解析、下载、摘要
校验、二进制格式校验、安装、配置和 live-handoff。

安全边界：

- 不执行远程脚本。
- 不根据网络返回值动态扩大兼容名单。
- 不覆盖兼容或不兼容的外部包管理器文件。
- 不在日志或安装器输出中打印机器 Key。
- 临时目录和配置使用 `umask 077`。
- 失败时尽可能保持安装前的二进制和配置状态。

## 8. 测试范围

构建和安装脚本测试至少覆盖：

- 四个平台的 Bundle 只包含 Pal、安装器和说明文件。
- 构建入口拒绝旧 Herdr 打包参数和非法版本、平台。
- 安装目录或 `PATH` 中存在兼容 Herdr 时直接复用且不下载。
- Herdr 缺失时自动下载、校验并安装。
- 不兼容 Herdr 存在时，接受更新后安装兼容版本。
- 不兼容 Herdr 存在时，拒绝更新且不产生安装副作用。
- 多个候选中后一个兼容时，不错误更新前一个外部候选。
- 下载失败、SHA-256 不符、平台不符、版本不符或协议不符时终止。
- Pal setup 失败时不继续 config check，并恢复本次替换的二进制。
- 运行中 Herdr 的 handoff 接受、拒绝和失败提示。
- README、默认 `/help` 和服务端帮助测试使用新的 Pal Bundle 名称和安装行为。

提交前执行 `./unittest.sh` 和 `./build.sh`。
