# dsh 接入安装前审核（2026-11-05，历史）

> **已被取代（2026-11-10）**：本文审核的是已删除的 Node 插件与 `internal/dshlegacy`。
> Pal 现直接使用 dsh 本机 Remote API，不再安装插件、读取 `dsh.token` 或依赖 Node.js。
> 当前方案见 [原生 API 设计](DSH_NATIVE_API_DESIGN.md)；以下内容仅保留历史记录。

范围：当前工作区 dsh 插件、Go 客户端与执行器、HPRP 组合路由、配置、构建与相关测试。
执行方式：主审与独立只读复核，不采用 subagent-driven 实现流程。

## 已修复阻断项

1. **P1：异步列表期间同 ID Agent 替换导致旧选择误投。** 两种确定性回归分别覆盖单次
   列表等待和并发列表交错。修复后固定 incarnation、身份记录对象和 Agent 实例，在恢复
   完成和输入提交前再次核验；测试由错误的 HTTP 200 转为 409，替换后的 Agent 不接收输入。
2. **P1：含助手回答的历史读取返回 HTTP 500。** dsh 0.2.1-rc.5 的 `assistant/message`
   使用 `data.message.content`，用户消息使用 `data.content`。按事件类型解析，并修正
   Node 及 Go 集成测试的 fake 事件结构，避免错误替身掩盖真实兼容问题。
3. **P1：慢历史恢复阻塞全部会话目录与读取。** 移除全局请求队列；幂等键在异步恢复前
   同步占位。目录与读取可独立进行，输入仍保持去重、忙碌和最终身份检查。

## 安装配套

新增可选 `tokenFile`：环境变量优先，否则从普通文件读取，POSIX 拒绝组或其他用户权限，
拒绝符号链接和过大文件。配置路径可保存在 dsh profile 中，凭据正文不写入仓库或 shell。

## 复核结论

上述修复已通过确定性回归和独立复核，当前未发现剩余阻断安装项。14 天过滤沿用 dsh
列表的 `updatedAt`；历史投影缓存缺失时 dsh 会回退创建时间。审批仍在 dsh 原界面处理。
真实模型输入不作为安装自检，避免向用户现有会话注入测试消息。

安装前运行 `./unittest.sh`（含 race）和 `./build.sh`。安装时保留旧二进制、Pal 配置与
dsh profile 备份，再验证插件加载、认证、目录读取及 Pal 的连接。

## 验证与本地安装结果

- `./unittest.sh`、`./build.sh` 通过，包含 14 项 Node 测试、全量 Go 单测与 race。
- 用户级 Pal 二进制与构建产物 SHA256 一致；dsh web profile 安装包源码与仓库一致。
- dsh 已热加载插件；认证列表返回 1 个 idle 会话，真实对话读取成功；错误 token 返回 401。
- Pal 原有启动器重启新二进制后，同时保持到本机插件与原 Relay Server 的连接。
- token 文件和 Pal 配置均为 `0600`；备份存放在用户级 state 目录，不进入 Git。
- 没有向用户真实 dsh 会话发送测试 prompt，也没有发送实际企微测试消息。

## 0.1.1 聊天正文范围修正

用户明确要求展示聊天内容、排除内部信息。新增纯提取模块，从原始 append 事件中保留
`source.kind=user` 的输入及助手 text 块；工具、推理、系统/开发者消息、技能/时间/目标
注入和压缩替换不进入输出。先过滤再限制最近 100 条，多轮聊天和分页仍保留。

18 项 Node 测试、全量 Go 单测、race 与构建通过；集成测试同时检查选择、`/con` 和通知
没有内部标记。插件更新后确认空闲并重启 dsh，真实会话输出由 3404 字符降至 112 字符，
正常提问与助手回答保留，Pal 到本机插件及 Relay 的连接正常。

## 0.1.2 内网部署复核

独立复核没有发现新的 P0/P1 阻断项。发现并修复一项 P2：OSC 8 超链接使用 ESC-ST 结束时，
贪婪清理正则可能跨越多个终止符，误删标签和中间正文。改为在第一个终止符结束；新增回归
同时覆盖 BEL 和 ESC-ST。19 项 Node 测试、全量 Go 单测、race 和 `build.sh` 均通过。

已对最终 `dist/dsh-herdr-pal-0.1.2.tgz` 验证离线交付：

- 环境：macOS、本机完整 dsh `0.2.1-rc.5`、Node.js `24.8.0`、pnpm `10.34.9`。
- 使用新建 `DSH_HOME` profile、空 pnpm store/cache，并将 registry 指向不可用回环端口。
- 安装与运行进程均由系统 sandbox 禁止出站网络连接。
- `dsh plugin --profile web add 本地包.tgz --offline --ignore-scripts` 返回 0，自动启用 bundle。
- 启动 dsh web 后，本机插件认证接口成功返回 protocol 1 的空会话目录；测试进程随即关闭。
- 安装源码摘要与仓库一致；已生成同名 `.tgz.sha256` 供复制到内网后核验。

插件不带 dsh、Node.js 或 pnpm，需预先准备完整宿主环境。仅插件可以离线安装；任务使用的
模型服务和中央 Server 的企微服务仍需可达。此次复核只在隔离环境验证最终包，未重启或
替换用户正在运行的 dsh 实例。详细步骤见插件 README 的“内网与离线导入”。
