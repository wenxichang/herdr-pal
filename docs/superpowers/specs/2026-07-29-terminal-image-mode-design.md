# 终端图片显示模式设计

## 1. 背景

Claude Code 和 Codex 等 Agent 通常会在选项前输出可见字符，移除 ANSI 控制序列后仍能
识别当前选项。OpenCode 等程序可能只依赖颜色、反色或其他 SGR 样式表示当前选项，现有
纯文本 `/con` 会丢失这些信息。

本设计为 Herdr Pal 增加终端图片显示模式。Pal 在本机读取包含安全 ANSI 样式的终端
快照并渲染 PNG，Server 保存用户对每个会话的显示模式并负责企业微信消息策略。HPRP
仍使用 `HPRP/1`；当前版本尚未公开发布，因此直接修订 v1 消息合同，不保留旧结构兼容
分支。

## 2. 目标与非目标

### 2.1 目标

- `/mode img` 把当前会话切换为图片模式，`/mode txt` 恢复文本模式。
- 模式只作用于一个完整 HPRP Target，不写入 Pal 配置或本地状态。
- Agent 名称不区分大小写等于 `opencode` 时默认使用图片模式，其他 Agent 默认使用文本
  模式。
- Pal 使用 `textimg`、16px 字体和 256 色 PNG8 在本机生成图片。
- 图片结果必须携带同一终端快照、同一页的规范化纯文本，供 Server 审计和文本降级。
- `/con`、`/pageup`、`/pagedn` 在文本和图片模式下保持一致的分页位置和内容变化检测。
- Pal 只上报状态变化；Server 决定是否通知、是否获取终端内容以及使用哪种模式。
- 不支持图片能力的连接仍能发送状态事件和文本终端内容。

### 2.2 非目标

- 本阶段不持久化终端正文，不实现审计记录、保留周期或敏感信息脱敏策略。
- 不把终端快照解释成结构化 LLM 消息或完整对话历史。
- 不针对 OpenCode 编写专用解析器，不识别具体菜单组件。
- 不在 Server 上渲染终端图片，也不保存 Pal 生成的图片文件。
- 不改变 Herdr 公共 Socket API 或依赖 Herdr 私有 TUI 状态。
- 不实现 HPRP/1 旧消息结构的运行时兼容。

## 3. 职责边界

### 3.1 Pal

Pal 负责：

- 从 Herdr 获取同一目标的纯文本和安全 ANSI 终端快照；
- 维护 `/con`、`/pageup`、`/pagedn` 的本地分页缓存；
- 按 Server 在单次请求中指定的模式返回文本或生成 PNG8；
- 检测 Agent 状态变化并只发送状态事件；
- 对状态通知的只读快照请求执行独立读取，不修改交互分页缓存。

Pal 不保存会话显示模式，不决定企业微信通知策略，也不上传企业微信媒体。

### 3.2 Server

Server 负责：

- 按用户和完整 HPRP Target 保存内存态显示模式；
- 处理 `/mode img`、`/mode txt` 和带 `/N`、`#N` 的定向模式命令；
- 接收状态变化事件并根据状态、当前选择、最近交互时间等策略决定通知形式；
- 需要终端内容时向 Pal 发起无副作用的快照请求，并在请求中指定 `txt` 或 `img`；
- 生成会话标题、全局序号、页码和会话不匹配提示；
- 上传企业微信临时图片并发送最终消息；
- 图片不可用时依据请求来源选择报错或文本降级。

Server 重启后模式覆盖丢失，按 Agent 默认值重新计算。会话消失或机器断开时立即删除对应
模式；同一 slot 发生经过确认的 session 替换时，把原会话的显式模式迁移到替换目标。

## 4. 状态通知数据流

Pal 不再在状态事件中主动附带终端正文：

```text
Herdr 状态变化
    -> Pal 发送 notification.event
    -> Server 去重、更新目录并计算通知策略
    -> 不需要内容：Server 直接发送状态通知或忽略
    -> 需要内容：Server 查询当前会话模式
        -> Server 发送 terminal.snapshot.get
        -> Pal 独立读取最近 100 行
        -> txt：返回同页纯文本
        -> img：返回同页纯文本和 PNG8
        -> Server 发送企业微信消息
```

`terminal.snapshot.get` 是只读操作，不等价于执行 `/con`。它不得重置页码、替换分页缓存
或改变下一次 `/pageup`、`/pagedn` 的结果。

Server 必须先处理状态事件，再决定是否获取内容。内容获取失败时不能丢失状态通知：

- 文本读取失败：发送不含终端正文的状态通知，并记录明确原因；
- 通知图片渲染失败：使用结果中同页纯文本降级发送；
- 企业微信图片上传失败：使用同页纯文本降级发送，并保留图片模式；
- 用户主动执行图片模式 `/con`、`/pageup` 或 `/pagedn` 时渲染失败：明确返回错误，不静默
  修改该会话模式。

参考实现保持现有通知体验，只把决策位置迁到 Server：

- `working` 发送状态说明，不请求终端快照；
- `done`、`blocked` 和需要展示输出的 `idle` 事件，经过现有去重和最近交互策略后再决定
  是否请求最近 100 行；
- `unknown` 不主动读取终端正文；
- 同一用户最近两分钟仍在其他会话交互时，非当前会话只发送“有新的输出”短提示，不请求
  大段终端快照；
- 用户输入、终端事件和成功返回的终端内容都会刷新该用户对应会话的最近交互时间。

## 5. HPRP/1 修订

### 5.1 能力协商

新增技术 capability：

- `terminal.snapshot.v1`：Server 可以请求某个稳定目标的无副作用终端快照；
- `terminal.image.v1`：Pal 可以在终端内容结果中内嵌有界 PNG 图片。

图片模式只有在双方协商 `terminal.image.v1` 后才能使用。用户显式执行 `/mode img` 时，
若当前 Pal 未协商该能力，Server 返回明确错误。Agent 的默认图片模式遇到旧能力连接时
自动按文本模式生效。

### 5.2 命令执行

`command.execute` 增加 `output_mode`，取值为 `txt` 或 `img`。它只决定本次命令产生的
终端内容格式，不改变 Pal 状态。Server 对 `/con`、`/pageup`、`/pagedn` 和 `/key` 后的
自动终端输出传递当前模式。

普通 prompt 的“消息已发送”等确认仍使用 `text/plain`，不因 `output_mode` 转成图片。

### 5.3 终端内容

HPRP/1 增加统一的终端内容对象：

```json
{
  "type": "terminal.snapshot",
  "mode": "img",
  "text": "同一页的规范化纯文本",
  "image": {
    "media_type": "image/png",
    "encoding": "base64",
    "data": "...",
    "width": 1280,
    "height": 720,
    "color_mode": "indexed"
  },
  "page": {
    "current": 1,
    "total": 5
  },
  "captured_at": "2026-07-29T10:00:00Z"
}
```

规则如下：

- `text` 始终必填，必须与图片来自同一目标、同一采集结果和同一页；
- `mode: txt` 时禁止携带 `image`；
- `mode: img` 时必须携带有效 PNG，除非整个请求以失败结果结束；
- 图片解码后不得超过双方协商限制，参考实现上限为 512 KiB；
- 纯文本不得超过 256 KiB，完整 JSON 帧仍不得超过连接的 1 MiB 上限；
- Base64、PNG 签名、尺寸、UTF-8 和分页字段必须严格校验；
- Server 可以使用 `text` 做审计、日志策略或失败降级，但参考实现当前不持久化正文。

### 5.4 状态事件与快照请求

`notification.event` 的 `agent.status.changed` 只携带状态元数据，不携带 `content`。事件
包含稳定 Target、旧状态、新状态、事件序号、事件时间和已确认的会话快照序号。

Server 使用 `terminal.snapshot.get` 请求最新终端内容，请求必须设置
`must_understand: true`，并包含：

- 稳定 Target；
- `mode`；
- `purpose: notification`；
- 最大行数，参考实现固定为 100。

Pal 使用 `terminal.snapshot.result` 返回一次最终结果。请求按只读操作处理，不使用命令
幂等键，但必须通过信封 `id`、`reply_to` 关联并受并发、大小和超时限制。目标已经变化、
消失或尚未同步时返回稳定目标错误，Server 不得把返回内容归到其他会话。图片渲染失败
但纯文本读取成功时，失败结果携带同次读取的 `fallback_content`，Server 可以仅在通知
场景把它降级为文本。

## 6. 模式命令语义

- `/mode img`：把当前选择会话设为图片模式；成功后返回确认，不自动执行 `/con`。
- `/mode txt`：把当前选择会话设为文本模式；成功后返回确认，不自动执行 `/con`。
- `/N /mode img`：对 N 号会话设置模式，成功后把当前选择切换到该会话。
- `#N /mode img`：对 N 号会话设置模式，不改变当前选择。
- 模式命令不能使用 `/N` 或 `/sel` 作为内部命令，沿用现有定向命令限制。
- 只有目标存在且模式变更成功时，`/N` 前缀才执行选择切换；失败时保持原选择并返回原因。

模式覆盖键使用 `(principal_id, machine_id, slot_id, session_id)`。默认模式根据会话快照中
的 Agent 名称计算，不写入覆盖表。

## 7. 终端读取与分页

Pal 对每个会话维护配对的终端行：

- 规范化纯文本行用于分页锚点、内容变化检测、审计文本和文本输出；
- 安全 ANSI 行用于图片渲染；
- 两组行在写入缓存前必须按逻辑行一一对齐。

ANSI 清理允许保留 SGR 颜色和样式，必须移除 OSC、DCS、终端标题、超链接、剪贴板、
光标移动和其他可能产生副作用或误导渲染器的控制序列。连续超过六个横线字符的文本
规范化规则继续生效。

分页行为保持现有语义：

- `/con` 读取最新内容，重置为最后一页；
- `/pageup` 读取更多历史内容并扩展当前缓存；内容锚点失效时提示重新执行 `/con`；
- `/pagedn` 只在当前缓存中向后翻页，不重新读取 Herdr；
- `/mode` 不读取终端、不重置缓存；
- 文本和图片模式切换后，同一页的页码和纯文本必须一致；
- `/key` 序列完成并等待既有延迟后刷新最后一页，随后按当前请求模式返回。

状态通知快照使用独立临时视图，不复用或修改上述分页状态。

## 8. 图片渲染

Pal 使用 `github.com/jiro4989/textimg/v3` 渲染终端图片，并通过 `go:embed` 内嵌
`Noto Sans Mono CJK SC Regular` 字体。仓库必须同时包含字体的 OFL 1.1 许可证和来源
说明。字体只被 Pal 渲染包引用，避免 Server 和 `hp-cli` 二进制包含字体数据。

参考实现参数：

- 字号 16px；
- 256 色索引 PNG8；
- 等宽中英文布局；
- 使用有界、快速的调色板量化，不采用高耗时的通用色彩优化；
- 背景、前景色和 SGR 样式来自清理后的 ANSI 终端内容；
- 输出只包含终端区域，企业微信标题和切换提示不绘制到图片中。

渲染器必须设置像素、行数、图片字节数和执行时间保护。超过硬限制时返回结构化错误，
不能生成无界图片或阻塞 HPRP heartbeat。

## 9. 企业微信发送

Server 收到图片终端内容后：

1. 使用企业微信智能机器人临时素材初始化接口取得上传标识；
2. 按接口限制分块上传 PNG；
3. 完成上传并取得 `media_id`；
4. 先发送包含 `[终端输出#N]`、机器、工作区、Agent、pane、页码和切换提示的文字消息；
5. 再使用 `media_id` 发送图片消息。

Server 不长期保存 PNG 或 `media_id`。同一结果只上传一次；HPRP 或企业微信重试必须使用
已有请求状态避免重复发送。企业微信适配层对上层暴露文本和图片两种内容，不把上传
协议混入路由器。

## 10. 竞态、去重与安全

- 状态事件必须通过 `event_key` 和目标内序号去重。
- Server 请求内容前再次确认目标仍在最新目录中。
- Pal 返回的 Target 必须与请求完全一致；不一致结果必须拒绝，不能只依据 slot 猜测。
- 状态事件到内容读取之间发生会话替换时，Pal 返回 `target.session_changed`，Server 只发
  状态说明或等待新会话事件。
- 状态通知快照是“处理事件时可读取到的最新终端视图”，不承诺冻结事件发生瞬间的屏幕。
- 日志只记录目标、模式、尺寸、耗时、页码和错误类别，不记录完整终端正文或 Base64。
- Server 收到的配对纯文本可供未来审计模块消费，但本阶段不写入数据库或文件。

## 11. 测试策略

### 11.1 协议测试

- HPRP v1 新 capability 的 hello 协商；
- `output_mode`、状态事件、快照请求和结果的严格 JSON 校验；
- 图片 Base64、PNG 签名、尺寸、大小、UTF-8 和同页文本必填校验；
- 未协商图片能力、目标变化、重复事件、响应关联和超限错误。

### 11.2 Pal 测试

- ANSI 安全过滤保留 SGR、移除 OSC/DCS/光标和超链接；
- 中英文、数字、颜色、反色和 256 色图片渲染；
- PNG8、字体嵌入、文件大小和渲染限制；
- 文本与图片使用同一页数据；
- `/con`、多次 `/pageup`、`/pagedn`、模式切换和动态输出组合；
- 通知快照不改变当前分页缓存；
- 状态事件不再主动携带终端正文。

### 11.3 Server 与企业微信测试

- 会话模式默认值、显式覆盖、替换迁移和断线清理；
- `/mode`、`/N /mode`、`#N /mode` 的成功与失败选择语义；
- 状态变化后由 Server 决定是否拉取内容；
- 文本、图片、渲染失败、上传失败和超时降级；
- 企业微信临时素材分块上传和图片消息发送；
- fake Pal、fake WeCom 下的完整状态通知和分页链路。

## 12. 发布边界

本次直接修改 HPRP/1 的消息定义、Go 类型和测试向量，不增加 HPRP/2，也不保留旧
`notification.event.content` 兼容逻辑。Pal 与 Server 完成改造后必须配套升级，后续公开
发布的 HPRP/1 以更新后的协议文档和 Schema 为准。
