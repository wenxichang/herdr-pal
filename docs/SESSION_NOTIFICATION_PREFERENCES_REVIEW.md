## R1 修正：空列表不删除开关

旧规则在 Pal 仍在线而后端暂时返回空目录时，会由 `/ls` 删除关闭记录，后端恢复后默认开启。当前删除必须同时满足：

1. 机器在线且已确认完整快照。
2. 该机器在本次同一目录视图中的列表非空。
3. 该业务组合没有出现在该机器的非空列表中。

条件按每台机器分别判断；另一台机器有会话不会让空列表机器进入删除范围。空列表、未同步或离线期间保留所有原有开关，恢复相同组合后仍沿用关闭状态。真正零会话的机器也暂不清理，等它后续列表非空时再删除缺失的旧组合。

实现位于 `internal/notificationprefs/store.go` 的 `Reconcile`，非空判定集中在存储事务中，而非依赖 Router 的全局列表长度。协议和 Pal 无变化。

回归测试：

- `TestStoreReconcileRequiresNonemptyListForEachMachine`：多机器混合视图只清理非空机器。
- `TestRouterListEmptyBackendPreservesReturningGroupMute`：空目录期间执行 /ls，恢复后 done 不读取或发送内容。
- `TestNotificationPreferencesPreserveMuteAcrossEmptySnapshotAndRecovery`：真实本地 HPRP 上报空目录、持久化检查和恢复后的静默状态。

保留的边界：非空列表不保证每个后端都健康；同一台机器仍有其他会话，但部分会话暂缺时，仍会按本次非空目录清理缺失组合。这符合此次指定条件，当前 Server 不额外推断后端健康状态。

| 组合身份 | 用户、机器、标题、工作区、Tab、CLI 类型参与匹配；编号和临时 Target 不参与持久化键。实际通知路径的隔离测试通过 |

| 批量命令 | 逗号/空格混用、去重和逐项跳过正常；显式编号全部无效不会回退修改当前选择；批量不改变选择 |

| 并发与原子性 | 同用户队列串行；目录锁不跨越磁盘/网络；Store 在文件替换前不发布候选状态，跨用户范围隔离 |
| 失效事件 | 只从当前或有界退出来源取身份；实际删除组合时清理退出来源，迟到事件不会恢复缺省开启而漏发 |
| 文件与恢复 | 版本、未知字段、无效/重复身份、缺失 enabled、尾随内容、不安全权限、符号链接和目录受到校验；空记录文件可重新加载 |
| 交付失败 | 设置成功但回复丢失时保留已提交状态；失败的列表不能启用未完整送达的编号映射 |
| 兼容性 | 无新增依赖；Pal、Herdr bridge、dsh 后端、HPRP 协议生产源码未改动；现有自定义 help.md 仍不覆盖 |
